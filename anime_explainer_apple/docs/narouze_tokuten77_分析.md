# narouze.com「Claude Codeで全自動」講座の分析（3回の深掘り）

出典：https://narouze.com/tokuten_line/77
「海外でバズっているアニメ解説動画の作成方法」（なろうぜくん）

---

## 1回目：全体の流れと狙い（何をする講座か）

**一言で**：ビジネス・金融の難しい話を「5歳でもわかる」レベルまで噛み砕き、クレヨン風のゆるいアニメで解説する動画を、Claude と Claude Code で作る講座。

**狙い（市場の読み）**
- 海外で流行ったフォーマットは、数か月遅れて日本でも伸びる傾向がある。海外では実証済みで、日本ではほぼ空席。
- 一度作った動画が資産になり、寝ている間も再生される（ストック型）。
- 英語は使わず、日本市場を狙う。

**作業は2ステップ**
1. テーマと台本：Claude に「テーマ決めプロンプト」→「台本プロンプト」を順に渡す。
2. 動画：ナレーション音声を作り、台本と音声をフォルダに入れ、Claude Code に「動画作成プロンプト」を渡す。

**講座が強調している注意点**
- 人物や数字は、AIが間違えることがある。投稿前に必ず自分で確認する。
- この構成なら必ず伸びる、ではない。投稿して数字を見て、自分の勝ちパターンを探す。
- Claude の有料プランが必要。最初の1か月は集中して取り組み、続けるか別ジャンルに移るかを決める。
- 音声サービスの API とつなげれば、台本から音声・編集まで全自動にできる。
- 今回の方法は、他のジャンルにもそのまま応用できる。

## 2回目：プロンプトの作り込み（なぜ結果が安定するか）

3つのプロンプトに共通する設計の考え方を取り出した。

### 共通
- **役割を与える**：「企画責任者」「脚本家」など、仕事の立場を最初に決める。
- **出力ルールを最初に、最重要として書く**：「番号付きタイトルだけ」「台本本文だけ」。前置き・解説・見出し・記号・話者名・演出メモを禁止し、そのまま次の工程に渡せる形にする。
- **判断基準は「頭の中で判断し、出力しない」**：テーマを選ぶ基準・自己チェック項目は、出力させずに内部で使わせる。
- **事前調査を指示**：Web検索で最新ニュース・数字を確認し、「今見る理由」を作る。
- **安全装置**：犯罪・不正が中心のテーマを除外、存命人物の評判を損なう内容を避ける、不確かな数字をタイトルに入れない、直接引用は台本全体で1回まで、投資話題には「売買をすすめるものではありません」、他チャンネルの台詞・表現は流用しない。

### ①テーマ決め
- 条件（名前は知られているが仕組みは知られていない／冒頭に巨大な数字／人間ドラマ／どん底と逆転／子どもにも例えられる／今見る理由）を満たすほど良いテーマ。
- 伸びやすいジャンルに順位をつける（金融危機・バブル崩壊 > 巨大テックの成り立ち・富豪の伝記 > 国家・経済の仕組み）。
- タイトルの型を指定（「◯◯を5歳でもわかるように解説」「◯◯は本当はどうやって◯◯を作ったのか」「何も売らずに◯◯円を稼いだ会社」）。
- 除外テーマ（作った／競合が作った）を入力で渡す。
- 選ぶときは「今ニュースになっている話題に乗る」。

### ②台本
- 長さ：6,000〜6,500字（15〜17分）。上限を決めて、長くなりすぎるのを防ぐ。
- **口調は「文章」ではなく「語り」**：深夜のドキュメンタリーで一人に語る人。語尾は「です・ます」＋「〜んです」「〜でした。」。テンションの高い口語は禁止。
- 7つの語りの技：語尾／語りかけ（想像してみてください）／間と溜め（短い一文の段落）／数字は1段落に1つまで・すぐ身近なスケールに置き換える／場面を描く／笑い（30〜60秒に1回・乾いたユーモア・真面目な場面ではふざけない）／リズム（一文40字まで）。
- **構成は14ブロック＋字数配分**（冒頭フック200字→原体験→転機→業界の仕組み→対立と決断→最初の製品→どん底の予兆→どん底→突破口→疑問への解説→大成功→試練→現在と論争→締め）。ブロックごとに「やること」が決まっている。
- 物語の質：主人公を最後まで中心に／前半の伏線を後半で回収／偶然の一致を活用／時系列は順番どおり。
- 出力前の自己チェック（本文以外の混入、字数、語りの硬さ、数字の詰め込み、笑い、主人公の消失、伏線、断定、直接引用）。

### ③動画作成（Claude Code）
- 初心者向けの配慮：日本語で短く、専門用語なし、インストール前に許可を取る。
- **キャラクター設定を入力で渡す**（案内役＋たとえ話の主人公）。実在人物・企業・他チャンネルのキャラに似せない。
- 仕様：1920×1080・30fps・mp4。絵はすべてコード（SVG）で描き、画像素材は使わない。3〜6秒ごとに絵が切り替わる。字幕は台本の文のまま。次の回も使い回せる仕組み。
- **3段階の仕組み**：①タイミング合わせ（音声の文字起こしと台本を照合して、文ごとの開始・終了秒を出す）→②絵コンテ（AIが書き、箇条書きで見せてOKをもらう）→③動画（Remotion）。
- **シーンの型（部品）**：title／talk／duo／list／compare／coins／pie／bars／news／keyword／outro。台本に合わなければ型を追加してよい。
- 絵コンテのルール：1カット3〜6秒、最初はtitle・最後はoutro、同じ型を3回以上続けない、背景色も続けて同じにしない、吹き出しは10文字前後に言い換える。
- 絵柄のルール：太い黒線・丸い角・平塗り＋右側だけの影／頭が大きく体が小さい／目は小さな縦長の丸／まばたきと口パクと上下の揺れ／フォントは Yusei Magic（手書き）と Zen Maru Gothic（字幕）／カメラ移動／要素は「ポンと出る・左から書かれる・自分で描かれる」／文字サイズ自動調整／字幕にかからない位置。
- **確認のしかた（必須）**：各カットから1コマずつ静止画を書き出して目で全部確認→直したらもう一度確認。開発サーバーは使わず、確認用の半分サイズmp4を出す。依存パッケージの脆弱性確認（npm audit）。
- 進め方：環境確認→台本と音声の確認→タイミング合わせ→絵コンテ（OK）→静止画確認→確認用mp4→感想を聞いて直す→本番書き出し→次回用のルールを CLAUDE.md にまとめる。

## 3回目：このプロジェクトに当てはめるときの穴と、一般化の方針

**講座どおりにやると詰まる点（実際にやって分かったこと）**
1. 文字起こし（whisper.cpp）はGitHubに届かない環境があった → **ElevenLabs の「文字ごとの時刻つき」音声生成**でタイミングを取る方が正確で速い。
2. 日本語の読み上げは、漢数字・数字・難読語・「……」で読み間違える → **「読み用の台本」（ひらがな化）と「字幕用の台本」を分ける**。文の数を同じにして、文の番号でひもづける。
3. 口パクを一定の速さで動かすと速すぎる → **音の大きさ（エンベロープ）に連動**させる。
4. 長い台本を1回で音声化すると失敗する → **約450字ずつに分けて生成してつなぐ**。
5. キャラの絵は凝るほど重く見える → **「シンプル版」（影・靴・眉・飾りなし）**を標準にして、特徴は1つにする。
6. ヘッドレスブラウザは外部フォントを取れない → **フォントを同梱**する。
7. 書き出しは約20分（6分の動画）。途中で環境が切れる前に、成果物を保存・送付する。

**講座に無い、足したほうがよい点**
- 「作った後の確認」を自動化（`tools/verify.py`）：文の数、カットの長さ、同じ型の連続、字幕の長さ、映像の仕様、音量、読み用台本に数字が残っていないか。
- 完成後に、声・読み・口の動き・事実を人が確認するチェックリスト。

**他のタイトル（ジャンル）に変わったときの考え方**
講座の3つのプロンプトは、どれも「**ジャンルごとに変わる部分**」と「**変わらない骨格**」に分けられる。

| 変わらない骨格 | ジャンルで変わる部分（`prompts/channels/<ジャンル>.md`） |
|---|---|
| 出力ルール（本文だけ）／判断基準は出力しない／事前調査／安全装置／3段階の仕組み／確認の手順 | 視聴者／テーマを選ぶ基準／ジャンルの優先順位／タイトルの型／台本の構成と字数／語りの口調／数字・用語の扱い／安全上の注意／読み方の変換表／使うシーンの型と配役／確認で追加する項目 |

- 例：ビジネス解説は「数字は1段落に1つ・丸めてよい」が、**料理は分量・時間・火加減を正確に**（音声・画面・字幕で一致）。安全装置も、投資の免責ではなく**食中毒・アレルギー・やけど・火の扱い**になる。
- 例：雑学は「クイズ→予想→答え→理由」の構成と、`quiz` シーンが主役。
- 新しいジャンルは `prompts/channels/_template.md` をコピーして作る。
