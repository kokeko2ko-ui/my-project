## 1. 最初にやること
```bash
git fetch origin && git checkout claude/quirky-wright-udpMD   # 作業は、そのセッションの作業ブランチで行い、終わったら PR で基準ブランチに取り込む
cd anime_explainer_apple && npm ci                         # package-lock.json あり。remotion 系は同じ版にそろえる
ffmpeg -version | head -1                                  # 無ければ入れる（音声の連結・速度変更に使う）
```
- 読む順：このファイル → `/.claude/skills/anime-explainer-video.md`（流れ・落とし穴）→ `prompts/README.md` → `prompts/channels/cooking.md`（形式B）→ `prompts/channels/cooking_facts.md`（確認済みの事実）。
- ElevenLabs：環境のプロキシがキーを差し込む（キーはダミー `xi-api-key: dummy` でよい）。長い台本は分割生成。
- Remotion は初回に Chrome Headless Shell を自分でダウンロードする（約90MB。`storage.googleapis.com` に届く環境）。
- フォントは `public/fonts` に同梱済み（ヘッドレスブラウザは外部フォントを取れない）。
- 書き出した mp4 は **リポジトリに入れていない**（`out/` は除外）。必要なら再書き出し：`EP=episodes/tamagoyaki_chef node tools/render.js final`（約12分／3分動画。バックグラウンドで）。
- `/mnt/user-data/outputs/` の動画は、環境が変わると消える。渡した動画はユーザーのチャットに残っている。

## 2. どこに何があるか
```
.claude/skills/anime-explainer-video.md   スキル本体（流れ・コマンド・落とし穴）
anime_explainer_apple/
  docs/narouze_tokuten77_分析.md          講座の3回の深掘り
  docs/参考動画の分析_シェフ番組.md        参考動画（実在の料理人）から取り出した雰囲気と、絵コンテ layout:"show" の書き方
  docs/引き継ぎ.md                        このファイル
  prompts/01_theme_prompt.md 02_script_prompt.md 03_video_prompt.md   3つのひな形
  prompts/channels/business.md cooking.md trivia.md _template.md      ジャンル別の設定
  prompts/channels/cooking_facts.md       料理の事実メモ（確認済み／できなかったこと／出典）
  episodes/<回の名前>/                     回ごとのデータ（下記）
  src/    Remotion の部品（Scenes.tsx=場面、Hud.tsx=台所番組の画面、Character.tsx、characters.ts=キャラ設定）
  tools/  tts_chunked.py make_timings.js make_envelope.js render.js verify.py make_reading.py reading_map.json upload_drive.js get_fonts.js
  public/ fonts と fonts.css（narration.mp3 は描画時にコピーされる。保存しない）
```
回のフォルダの中身：`input/script.txt`（字幕用・漢字まじり）／`input/script_reading.txt`（読み用・ひらがな化）／`voices.json`（掛け合いの声）／`narration.mp3`／`timings.json`／`envelope.json`／`storyboard.json`／`out/`（除外）。

## 3. 制作の手順（1本作る）
```bash
export EP=episodes/<名前>
# 1) 台本を input/script.txt に（掛け合いは「シェフ：…」「後輩：…」の行）
python3 tools/make_reading.py $EP      # 読み用の台本を自動で作る（回だけの変換は $EP/reading_extra.json）
python3 tools/tts_chunked.py           # 声を作ってつなぐ（掛け合いは voices.json で話者ごとの声、約1.2倍に速める）
node tools/make_timings.js && node tools/make_envelope.js
# 2) storyboard.json を書く → ユーザーに箇条書きで見せて OK をもらう
node tools/render.js stills            # 全カットの静止画 → 目で全部確認（6〜9枚ずつ1枚にまとめて見ると速い）
python3 tools/verify.py $EP            # 自動確認（FAIL は直す）
node tools/render.js final             # 本番（run_in_background）
# 3) 720p の軽い版を作り、/mnt/user-data/outputs/ に ASCII 名でコピーして SendUserFile
```
- 台本を直すと文の番号がずれる。**絵コンテは文の番号 `s` で動くので、直したら必ず作り直す**（`difflib` で旧→新の文を対応づけた。実例は会話の履歴ではなく、考え方：同じ文は同じ文に、置き換わった文から始まるカットは次の同じ文に合わせ、クイズの reveal は「正解の文の開始時刻」から再計算）。

## 6. 落とし穴（実際に踏んだもの）
- **動画は私には見られない・聞けない。** 参考動画も YouTube のボット確認でダウンロード不可。字幕・サムネイル・途中の静止画（`i.ytimg.com/vi/<id>/hq1.jpg` など）だけ取れた。確認した範囲を正直に伝える。「全体を見た・聞いた」と言わない。
- Eleven v4 は `speed` 設定を無視する → 音声を ffmpeg の `atempo` で速める。
- 長い台本の音声は 502 になる → 分割生成（`tts_chunked.py`）。502 は自動で再試行。
- **ひらがな「さとう」は人名の読み**になる。難読語・数字は読み用の台本で直すが、何でもひらがなにすると別の読みになることがある。
- 絵コンテのキー `from` は、動画側で計算するカット開始フレーム `from` とぶつかる（`coins` 場面は `src` を使う）。
- 台本を直したら、静止画を全部撮り直して見る（古い静止画が残ると、見たつもりになる）。`verify.py` の「静止画がない」警告を見逃さない。
- 日本語のファイル名は SendUserFile で化けることがある → ASCII 名で送る。
- ALIC のページは Shift_JIS → `curl` で取って `iconv -f CP932 -t UTF-8` で読む（WebFetch は化ける）。
- 書き出し中にフォルダ名を変えない。進捗ログのファイルを消さない。
- 背景で動かすコマンドは `run_in_background` で。`nohup … &` + `sleep` だと、シェルと一緒に見えなくなる。

## 7. 事実確認の方針
- 出典のないブログだけを根拠にしない。公的機関・大学の資料を探し、見つからなければ「言われている」と書く。
- 料理は先に `prompts/channels/cooking_facts.md`。**確認済みは3つ**：①砂糖は水を抱え込み、たんぱく質の熱凝固を抑える（ALIC）。②上白糖は転化糖1〜3%で、焼き色がつきやすい（ALIC。河田昌子『お菓子「こつ」の科学』を参照した記事も一致。本の原文は未確認）。③卵黄は約65℃で固まり始める。
- **確認できていない**：卵白の凝固開始温度（55〜75℃と資料で幅）、砂糖の量と焼き色の関係の数値、卵焼きで砂糖が焦げやすさをどれだけ増やすか。
- 「焦げやすい」とは言わない。「焼き色がつきやすい」と言う。

## 8. 環境・秘密情報
- ElevenLabs：プロキシ差し込み（環境設定の Network secrets）。
- `www.googleapis.com` の Network secret：前回ユーザーが保存した Drive 用トークン（約1時間で失効）。ユーザーは設定画面から削除できる。トークンをチャットに貼らせない。
- Remotion は Chrome を自分で取得。`/opt/pw-browsers` の Chromium は使っていない（`render.js` が探すが、取得済みの方が使われる）。

## 9. ユーザーの好み・口調
- 日本語で、専門用語を使わず、短く。結果→理由→確認できていないこと→次に決めてほしいこと、の順。
- 動画を渡すときは、チャットにファイルを添付（720pの軽い版を先に。1080pは大きい）。
- 動画ができたら、確認した範囲と、確認できていないことを分けて書く。
